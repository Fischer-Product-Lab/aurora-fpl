# Portfolio screenshot plan

The public [Aurora Run Explorer](https://aurora-agent-run-explorer.t-fischer2.chatgpt.site/)
is the source of truth. These named slots keep future screenshots stable across
the root README, a Fischer Product Lab case study, and social posts without
committing arbitrary work-in-progress captures.

## 1. Dashboard overview

**Target file:** `dashboard-overview.png`

Capture the top of the clean-orchestration story at a desktop width. Include the
Fischer Product Lab header, business-language introduction, guided story rail,
and outcome summary. This is the primary repository and portfolio image.

**Suggested caption:** “A business-first view of one agent run, with the outcome
and the safeguards that produced it.”

## 2. Trace and evidence

**Target file:** `trace-and-evidence.png`

Capture a faulted planning run with the readable timeline and evidence panel in
view. The image should make the independent critic's detection and bounded
repair legible without depending on the raw JSON tab.

**Suggested caption:** “The trace connects a planning omission to review,
repair, governed execution, and verification.”

## 3. Budget denial

**Target file:** `budget-denial.png`

Capture the tight-budget story where fallback admission is denied before work
starts. Include the zero-use budget result and the safely degraded outcome.

**Suggested caption:** “A scoped reservation blocks unaffordable fallback
before dispatch, preventing partial work and overspend.”

## Capture checklist

- Use the same desktop viewport and browser zoom for all three images.
- Keep browser chrome, local paths, account information, and debug tooling out
  of frame.
- Prefer the default light theme unless the portfolio page uses dark imagery.
- Re-capture all three images after material layout or copy changes.
- Optimize PNG files before committing them; screenshots should remain readable
  at the width used by the portfolio.
